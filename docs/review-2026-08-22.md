# Multi-agent review, 2026-08-22 — overengineering audit

Trigger (owner): field results got worse run after run despite every unit
test passing. Suspicion: the rules added run-by-run during the day now
interact badly. Four independent review lenses (rule conflicts, suspect
pipeline, physics fidelity, economy) read the code and reported 40
findings; each was verified adversarially where the budget allowed.

Status legend: **FIXED** (shipped with a red-first test), **ADJUDICATED**
(examined and found not to be a defect, with the reasoning), **PENDING**
(documented here with reason and plan — nothing is dropped silently).

## The structural diagnosis

Every field bug of 2026-08-22 lived in a *seam*, not in a rule. Three
compounding causes:

1. **Two clocks.** Animation windows (confetti, garra reveal) were
   expressed in `done`, which counts actions, not frames. A three-tap
   batch aged them three times, so confetti protection evaporated
   exactly when the bot moved fastest.
2. **Half the pipeline was shift-aware.** Stages that compared last
   frame's cells to this frame's cells split into those that compensated
   for the scroll and those that did not, so beliefs silently
   disagreed after every move.
3. **Rules added per-run without a shared predicate.** Positioning and
   firing, suspicion and routing, waiting and exploring — each pair was
   written in a different run against a different symptom, and they now
   veto each other. The livelock of the forming-wall rule (walk to a
   launch the dash gate then refuses) is the clearest example.

The suspect pipeline is where this concentrates: six mechanisms
(appearances, carryover, burst holds, sticky holds, remembered-drops,
decay) exist to compensate for shift uncertainty that the pixel scroll
sensor already eliminated. See PENDING-1.

## ADJUDICATED (examined, no change warranted)

- **"Router charges phantom scrolls prunes legal routes"** — the
  mispricing is real (fixed above), but the claimed consequence is not
  reachable: the error only fires on a right step taken after a left
  step that followed a scroll, and on a 5×5 Manhattan grid that zigzag
  is never on an optimal route. Documented in the test rather than
  claiming an impact that does not exist.
- **The two walk-back taps of run 20260822T215547** — the wall only
  materialised in n=52 as the scrolls brought it in; those taps were the
  minimum positioning, not waste. The waste in that run was the explore
  garra (fixed separately).

## PENDING (with reason and plan — revisit before adding any new rule)

**PENDING-1 — DONE (same day).** The six-mechanism suspect stack is
gone, replaced by `world_model.py`: every entity is a track whose
identity survives the measured scroll and survives being covered, and
whose origin is decided once at birth. Deleted: `suspect_appearances`,
`combined_suspects`, `burst_holds`, `sticky_left_band_suspects`,
`drop_remembered_suspects`, `decay_unseen_left_band`,
`remember_confirmed_items`, `prune_remembered_items`,
`drop_shift_ghosts`, `confetti_rows_of`, `dash_pickup_log`,
`remember_revealed_pickup`, plus the `mem_misses`, `sticky_ages`,
`prev_fresh_suspects`, `prev_suspect_items` and `prev_item_cells`
state — about 900 lines including the 13 test classes that pinned
them, against ~100 added. The pixel sensor already measured the scroll
these mechanisms existed to guess at.

What replaced each behaviour, so nothing is lost: identity across the
scroll and across cover replaces shift ghosts, sticky ages and the
decay's miss counting; origin decided once replaces fresh appearances,
the two-frame carryover, burst holds and the reveal whitelist; a
believed track never being re-litigated replaces the
memory-outranks-suspicion rule and its tap-gate exemption; standing on
a cell ending its track replaces the memory pops and the contradiction
rules. Occlusion (an oversized partner's body) is now stated as
"unobservable", which is what it always was — it used to be
compensated by hand-feeding memory.

The model also carries the planning surface that was missing: the
sixth-column preview is kept as a prediction, confirmed when the
pyramid lands, and `incoming_wall(row)` reports what has landed, what
is still promised, whether it is dashable, and whether it would erode
if the bot scrolls again — the shape that cost two pyramids in run
20260822T234822.

**PENDING-2 — Unify the erosion veto.** Five dash rules and two runner
overrides each compute their own "would this scroll erode something
real" set, with three different policies on steps cards. One predicate,
one call site. Deferred with PENDING-1 because both touch the same call
sites and doing them separately means two migrations of the same tests.

**PENDING-3 — One economy constants block.** Steps-card value (+4
paticas / 160 shards), garra 200, dash 400, move 40 and the measured
dash energy yield are restated inline at six sites, and two of them
disagree. Mechanical but wide; batched with PENDING-2.

**PENDING-4 — CLOSED 2026-08-23 with the run it asked for.** Run
20260823T074036 n=154-157 and n=80-83: `suspect_risk` vetoed the dash for a
left-band suspect while `should_hold_for_suspects` refused to wait for the

**PENDING-4 — Contradictory wait doctrines.** `should_hold_for_suspects`
says left-band suspects are never worth waiting for, while `choose()`

one requires a run where they conflict, which the corpus does not yet
contain. Watch item: add the run that shows it, then decide with
evidence rather than by argument.
